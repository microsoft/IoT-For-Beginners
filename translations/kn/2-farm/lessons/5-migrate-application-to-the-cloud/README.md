## ಸರ್ವರ್‍ಲೆಸ್ ಎಂದರೆ ಏನು?

ಸರ್ವರ್‍ಲೆಸ್ ಅಥವಾ ಸರ್ವರ್‍ಲೆಸ್ ಕಂಪ್ಯೂಟಿಂಗ್ ಅಂದರೆ ಬಣ್ಣೋವ ಬಿಗ್ಗಮನ ಮಾಡಲು ಬಣ್ಣೋವ ಸಂದಡ್ಡಿಗಳ ಫಲವಾಗಿ ಕ್ಲೌಡ್‌ನಲ್ಲಿ ಚಲಿಸುವ ಸಣ್ಣ ಮಾದರಿಯ ಕೋಡ್ ಬ್ಲಾಕ್ಗಳನ್ನು ರಚಿಸುವುದು. ಸಂಧ್ಯಾ ಸಂಭವಿಸಿದಾಗ ನಿಮ್ಮ ಕೋಡ್ ಅನ್ನು ನಿರ್ವಹಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಅವರಿಗೆ ಈ ಘಟನೆ ಬಗ್ಗೆ ಡೇಟಾ ನೀಡಲಾಗುತ್ತದೆ. ಈ ಸಂಭವಗಳು ವೆಬ್ ವಿನಂತಿಗಳು, ಕ್ಯೂ ಮೇಲೆ ಪ್ರಕಟಿತ ಸಂದೇಶಗಳು, ಡೇಟಾಬೇಸ್ ನಲ್ಲಿ ಡೇಟಾ ಬದಲಾವಣೆಗಳು, ಅಥವಾ ಐಒಟಿ ಸಾಧನಗಳಿಂದ ಐಒಟಿ ಸೇವೆಗಳಿಗೆ ಕಳುಹಿಸಿದ ಸಂದೇಶಗಳು ಮುಂತಾದ ಹಲವಾರು ವಿಧಗಳಾಗಿರಬಹುದು.

![ಐಒಟಿ ಸೇವೆಯಿಂದ ಸರ್ವರ್‍ಲೆಸ್ ಸೇವೆಗೆ ಸಂದೇಶಗಳನ್ನು ಕಳುಹಿಸುವುದು, ಅದನ್ನು ವಿವಿಧ ಫಂಕ್ಷನ್ಗಳು ಸಮಕಾಲೀನವಾಗಿ ನಿರ್ವಹಿಸುತ್ತಿವೆ](../../../../../translated_images/kn/iot-messages-to-serverless.0194da1cc0732bb7.png)

> 💁 ನೀವು ಮೊದಲು ಡೇಟಾಬೇಸ್ ಟ್ರಿಗರ್ಸ್ ಬಳಸಿ থাকಿಲೇ, ಇದನ್ನು ಅದೇ ರೀತಿಯಾಗಿ ಪರಿಗಣಿಸಬಹುದು, ಘಟನೆಯಿಂದ ಪ್ರೇರಿತವಾಗುವ ಕೋಡ್, ಉದಾಹರಣೆಗೆ ಸಾಲನ್ನು ಸೇರಿಸುವಾಗ.

![ಹಲವಾರು ಸಂದೇಶಗಳನ್ನು ಸಮಕಾಲೀನವಾಗಿ ಕಳುಹಿಸಿದಾಗ, ಸರ್ವರ್‍ಲೆಸ್ ಸೇವೆ ಅಂಗಡಿಗಳನ್ನು ಹರಡುತ್ತದೆ](../../../../../translated_images/kn/serverless-scaling.f8c769adf0413fd1.png)

ನಿಮ್ಮ ಕೋಡ್ ಆ ಘಟನೆಯಾಗುವಾಗ ಮಾತ್ರ ಚಲಿಸುತ್ತದೆ, ಇತರೆ ಸಮಯದಲ್ಲಿ ನೀವು ಯಾವುದೇ ನಿಮ್ಮ ಕೋಡ್ ಜೀವಂತವಾಗಿರಿಸುವುದಿಲ್ಲ. ಘಟನೆಯಾಗುವಾಗ, ನಿಮ್ಮ ಕೋಡ್ ಲೋಡ್ ಆಗಿ ಚಲಿಸುತ್ತದೆ. ಇದರಿಂದ ಸರ್ವರ್‍ಲೆಸ್ ಬಹಳವೇ ಪರಿಮಾಣ ದಕ್ಷವಾಗಿರುತ್ತದೆ - ಅನೇಕ ಘಟನೆಗಳು ಸಮಕಾಲೀನವಾಗಿ ಸಂಭವಿಸಿದರೆ, ಕ್ಲೌಡ್ ಒದಗಿಸುವವರು ನಿಮ್ಮ ಕಾರ್ಯವನ್ನು ಒಪ್ಪಿಗೆಯಾದಷ್ಟು ಸರ್ವರ್‍ಗಳಲ್ಲಿ ಸಮಕಾಲೀನವಾಗಿ ನಡೆಸಬಹುದು. ಇದರ ದೋಷವೆಂದರೆ ಘಟನೆಗಳ ನಡುವೆ ಮಾಹಿತಿಯನ್ನು ಹಂಚಿಕೊಳ್ಳಬೇಕಾದರೆ, ಅದನ್ನು ಮೆಮೊರಿಯಲ್ಲಿ ಸಂಗ್ರಹಿಸುವ ಬದಲು ಡೇಟಾಬೇಸ್ ನಲ್ಲಿ ಉಳಿಸುವ ಅಗತ್ಯವಿರುತ್ತದೆ.

ನಿಮ್ಮ ಕೋಡ್ ಘಟನೆಯ ವಿವರಗಳನ್ನು ಪ್ಯಾರಾಮೀಟರ್ ಆಗಿಟ್ಟುಕೊಂಡು ಕಾರ್ಯವಾಗಿರುವ ಫಂಕ್ಷನ್ ಆಗಿ ಬರೆದಿರುತ್ತದೆ. ನೀವು ಬಹು ವಿಧದ ಪ್ರೋಗ್ರಾಮಿಂಗ್ ಭಾಷೆಗಳನ್ನು ಬಳಸಿಕೊಂಡು ಈ ಸರ್ವರ್‍ಲೆಸ್ ಫಂಕ್ಷನ್ಗಳನ್ನು ಬರೆಯಬಹುದು.

> 🎓 ಸರ್ವರ್‍ಲೆಸ್ ಅನ್ನು_Functions as a service (FaaS)_ ಎಂದೂ ಕರೆಯಲಾಗುತ್ತದೆ ಕಾರಣ ಪ್ರತಿ ಘಟನೆ ಪ್ರೇರಣೆಯನ್ನು ಕೋಡ್ ನಲ್ಲಿ ಫಂಕ್ಷನ್ ಆಗಿ ಅನುಷ್ಠಾನಗೊಳಿಸಲಾಗುತ್ತದೆ.

ಹೆಸರಿನ ವಿರುದ್ಧವಾಗಿ, ಸರ್ವರ್‍ಲೆಸ್ ನಿಜವಾಗಿಯೂ ಸರ್ವರ್ ಗಳನ್ನು ಉಪಯೋಗಿಸುತ್ತದೆ. ಹೆಸರಿನ ಅರ್ಥವೆಂದರೆ ನೀವು ಡೆವಲಪರ್ ಆಗಿ ನಿಮ್ಮ ಕೋಡ್ ಚಾಲನೆ ಮಾಡಲು ಅಗತ್ಯವಿರುವ ಸರ್ವರ್ ಗಳ ಬಗ್ಗೆ ಚಿಂತಿಸುವ ಅಗತ್ಯವಿಲ್ಲ, ನೀವು ಗಮನಿಸುವುದು ನಿಮ್ಮ ಕೋಡ್ ಘಟನೆಗೆ ಪ್ರತಿಕ್ರಿಯಿಸಿ ಕಾರ್ಯನಿರ್ವಹಿಸುವುದು ಮಾತ್ರವಾಗಿದೆ. ಕ್ಲೌಡ್ ಒದಗಿಸುವವರು ಸರ್ವರ್‍ಲೆಸ್ *ರನ್ ಟೈಮ್* ಹೊಂದಿರುತ್ತಾನೆ ಅದು ಸರ್ವರ್ ಗಳ ನಿಯೋಜನೆ, ನೆಟ್ವರ್ಕಿಂಗ್, ಸಂಗ್ರಹಣೆ, ಸಿಪಿಯು, ಮೆಮೊರಿ ಮತ್ತು ಇತರ ಎಲ್ಲ ಮೌಲ್ಯಗಳನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ. ಈ ಮಾದರಿಯಲ್ಲಿ ನೀವು ಸರ್ವರ್ ಪ್ರತಿ ಪಾವತಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ, ಏಕೆಂದರೆ ಇಲ್ಲ ಸರ್ವರ್ ಇಲ್ಲ. ಬದಲಾಗಿ, ನೀವು ನಿಮ್ಮ ಕೋಡ್ ಚಲಿಸುವ ಸಮಯ ಮತ್ತು ಬಳಸಿದ ಮೆಮೊರಿ ಪ್ರಮಾಣಕ್ಕೆ ಪಾವತಿಸುತ್ತೀರಿ.

> 💰 ಸರ್ವರ್‍ಲೆಸ್ ಕ್ಲೌಡ್ ನಲ್ಲಿ ಕೋಡ್ ಚಾಲಿಸಲು ಒಂದು ಅತಿಥೀಮೂಲ್ಯದ ವಿಧಾನ. ಉದಾಹರಣೆಗೆ, ಬರೆಯುವ ಸಮಯದಲ್ಲಿ, ಒಂದು ಕ್ಲೌಡ್ ಒದಗಿಸುವವರು ಎಲ್ಲಾ ನಿಮ್ಮ ಸರ್ವರ್‍ಲೆಸ್ ಫಂಕ್ಷನ್ಗಳನ್ನು ಒಟ್ಟು 1,000,000 ಬಾರಿ ತಿಂಗಳಿಗೆ ಚಾಲನೆ ಮಾಡಲು ಅನುಮತಿಸುತ್ತಾರೆ ನಂತರ ಅದಕ್ಕೆ $0.20 ದರ ಸುತ್ತ 1,000,000 ಚಾಲನೆಗಳಿಗಾಗಿರುತ್ತದೆ. ನಿಮ್ಮ ಕೋಡ್ ಕಾರ್ಯನಿರ್ವಹಿಸದಾಗ, ನೀವು ಪಾವತಿಸುವುದಿಲ್ಲ.

ನೀವು ಐಒಟಿ ಡೆವಲಪರ್ ಆಗಿದ್ದಲ್ಲಿ, ಸರ್ವರ್‍ಲೆಸ್ ಮಾದರಿ ಅತ್ಯುತ್ತಮವಾಗಿದೆ. ನೀವು ಚರ್ಚೆಯ ಅಂಶವನ್ನು ಓದುತ್ತಿರಿ, ನಿಮಗೆ ಅನೇಕ ಐಒಟಿ ಸಾಧನಗಳಿಂದ ಕಳುಹಿಸಿದ ಸಂದೇಶಗಳಿಗೆ ಪ್ರತಿಕ್ರಿಯಿಸುವ ಫಂಕ್ಷನ್ ಬರೆಯಬಹುದು. ನಿಮ್ಮ ಕೋಡ್ అన్ని ಸಂದೇಶಗಳನ್ನು ನಿಭಾಯಿಸುತ್ತದೆ ಆದರೆ ಅಗತ್ಯವಿದ್ದಾಗ ಮಾತ್ರ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ.

✅ ನೀವು ಚಿತ್ರಿಸಿದ ಕೋಡ್ ಅನ್ನು ನೆನಪಿಡಿ, ಅದು MQTT ಮೂಲಕ ಸಂದೇಶಗಳನ್ನು ಕೇಳುವ ಸರ್ವರ್ ಕೋಡ್ ಆಗಿತ್ತು. ಇದೇ ಸರ್ವರ್‍ಲೆಸ್ ಮೂಲಕ ಕ್ಲೌಡ್ ನಲ್ಲಿ ಹೇಗೆ ಚಲಿಸಬಹುದು? ಕೋಡ್ ಹೇಗೆ ಬದಲಾಯಿಸಬಹುದು ಎಂದು ನೀವು ಎಷ್ಟು ಭಾವಿಸುತ್ತೀರಿ?

> 💁 ಸರ್ವರ್‍ಲೆಸ್ ಮಾದರಿ ಇನ್ನು ಹಲವು ಕ್ಲೌಡ್ ಸೇವೆಗಳಲ್ಲಿ ಸಕ್ರಿಯವಾಗಿದೆ. ಉದಾಹರಣೆಗೆ, ಸರ್ವರ್‍ಲೆಸ್ ಡೇಟಾಬೇಸ್ ಗಳು ಈಗ ಕ್ಲೌಡ್ ನಲ್ಲಿ ಲಭ್ಯವಿವೆ ಮತ್ತು ಅದರಲ್ಲಿ ನೀವು ಡೇಟಾಬೇಸ್ ವಿರುದ್ಧ ಮಾಡಿದ ಪ್ರತಿಯೊಂದು ವಿನಂತಿಗೆ ಪಾವತಿಸುತ್ತೀರಿ, ಉದಾಹರಣೆಗೆ ಕ್ವೇರಿ ಅಥವಾ ಸೇರಿಸುವಿಕೆ. ಸಾಮಾನ್ಯವಾಗಿ ಇದಕ್ಕೆ ಈ ವಿನಂತಿಗಳನ್ನು ನಿರ್ವಹಿಸಲು ಆಗುವ ಕೆಲಸದ ಪ್ರಮಾಣದ ಆಧಾರದ ಮೇಲೆ ದರ ನಿಗದಿಯಾಗುತ್ತದೆ. ಉದಾಹರಣೆಗೆ ಪ್ರಾಥಮಿಕ ಕೀಲಿಗೊಂದು ಸಾಲು ಆಯ್ಕೆ ಮಾಡುವುದು, ಹಲವಾರು ಪಟ್ಟಿಕೆಗಳು ಸೇರಿಸಿ ಸಾವಿರಾರು ಸಾಲುಗಳನ್ನು ಹಿಂತಿರುಗಿಸುವುದಕ್ಕಿಂತ ಕಡಿಮೆ ವೆಚ್ಚವಾಗುತ್ತದೆ.

ಕೆಳಗಿನ ಚಿಕ್ಕ ವೀಡಿಯೋದಲ್ಲಿ Azure Functions ನ ಅವಲೋಕನ ದೊರೆಯುತ್ತದೆ

[![Azure Functions ಅವಲೋಕನ ವೀಡಿಯೋ](https://img.youtube.com/vi/8-jz5f_JyEQ/0.jpg)](https://www.youtube.com/watch?v=8-jz5f_JyEQ)

> 🎥 ವೀಡಿಯೋ ನೋಡಲು ಮೇಲಿನ ಚಿತ್ರವನ್ನು ಕ್ಲಿಕ್ ಮಾಡಿ

✅ ಸ್ವಲ್ಪ ಸಮಯ ತೆಗೆದುಕೊಂಡು [Microsoft Azure Functions ಡಾಕ್ಯುಮೆಂಟೇಶನ್](https://docs.microsoft.com/azure/azure-functions/functions-overview?WT.mc_id=academic-17441-jabenn) ನಲ್ಲಿ Azure Functions ನ ಅವಲೋಕನ ಓದಿ ಅಧ್ಯಯನ ಮಾಡಿರಿ.

Azure Functions ಬರೆಯಲು, ನಿಮ್ಮ ಆಯ್ಕೆಯ ಭಾಷೆಯಲ್ಲಿ Azure Functions ಆ್ಯಪ್ ಮೂಲಕ ಪ್ರಾರಂಭಿಸಿರಿ. Azure Functions ಬಾಕ್ಸಿನಿಂದ Python, JavaScript, TypeScript, C#, F#, Java ಮತ್ತು Powershell ಭಾಷೆಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ. ಈ ಪಾಠದಲ್ಲಿ ನೀವು Python ನಲ್ಲಿ Azure Functions ಆ್ಯಪ್ ಬರೆಯುವುದನ್ನು ಕಲಿಯುತ್ತೀರಿ.

> 💁 Azure Functions ಕಸ್ಟಮ್ ಹ್ಯಾಂಡ್ಲರ್ ಗಳನ್ನು ಸಪೋರ್ಟ್ ಮಾಡುತ್ತದೆ, ಆದ್ದರಿಂದ ನೀವು HTTP ವಿನಂತಿಗಳನ್ನು ಬೆಂಬಲಿಸುವ ಯಾವುದೇ ಭಾಷೆಯಲ್ಲಿ ನಿಮ್ಮ ಫಂಕ್ಷನ್ಗಳನ್ನು ಬರೆಯಬಹುದು, ಹಳೆಯ ಭಾಷೆಗಳು ಹಾಗೆ COBOL ಸಹ.

ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ನಲ್ಲಿ ಒಂದು ಅಥವಾ ಹೆಚ್ಚು *ಟ್ರಿಗರ್* ಗಳಿರುತ್ತವೆ - ಘಟಗಳಿಗೆ ಪ್ರತಿಕ್ರಿಯಿಸುವ ಫಂಕ್ಷನ್ಗಳು. ನೀವು ಒಂದೇ ಆ್ಯಪ್ ನಲ್ಲಿ ಒಷ್ಟು ಟ್ರಿಗರ್ ಗಳನ್ನೂ ಇರಿಸಬಹುದಾಗಿದೆ, ಮತ್ತು ಅದರಲ್ಲಿನ ಎಲ್ಲವೂ ಸಾಮಾನ್ಯ ಸಂರಚನೆಯನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ. ಉದಾಹರಣೆಗೆ ನಿಮಗಿರುವ Functions ಆ್ಯಪ್ ಸಂರಚನಾ ಫೈಲ್ ನಲ್ಲಿ ನಿಮ್ಮ ಐಒಟಿ ಹಬ್ ಕನೆಕ್ಷನ್ ವಿವರಗಳಿರಬಹುದು, ಮತ್ತು ಆ ಆ್ಯಪ್ನಲ್ಲಿನ ಎಲ್ಲ ಫಂಕ್ಷನ್ಗಳು ಈ ಸೇವೆಗಳಿಗೆ ಸಂಪರ್ಕ ಹೊಂದಿ ಘಟನಗಳಿಗೆ ಕೇಳಬಹುದಾಗಿರುತ್ತವೆ.

### ಕಾರ್ಯ - Azure Functions ಉಪಕರಣಗಳ ಸ್ಥಾಪನೆ

> ಬರೆಯುತ್ತಿರುವ ಕ್ಷಣದಲ್ಲಿ, Azure Functions ಕೋಡ್ ಉಪಕರಣಗಳು Apple Silicon ನಲ್ಲಿ Python ಪ್ರಾಜೆಕ್ಟ್ ಗಳಿಗೆ ಸಂಪೂರ್ಣ ಕಾರ್ಯನಿರ್ವಹಿಸುವುದಿಲ್ಲ. ನೀವು Intel ಆಧಾರಿತ ಮಾಕ್, ವಿಂಡೋಸ್ ಪಿಸಿ ಅಥವಾ ಲಿನಕ್ಸ್ ಪಿಸಿ ಬಳಸಬೇಕು.

Azure Functions ನ ಒಂದು ಅದ್ಭುತ ವೈಶಿಷ್ಟ್ಯವೆಂದರೆ ಅವುಗಳನ್ನು ಸ್ಥಳೀಯವಾಗಿ ಚಾಲನೆ ಮಾಡಬಹುದು. ಕ್ಲೌಡ್‌ನಲ್ಲಿ ಉಪಯೋಗವಾಗುವ ರನ್‍ಟೈಮ್ ನ್ನು ನಿಮ್ಮ ಕಂಪ್ಯೂಟರ್‌ನಲ್ಲಿ ಓಡಿಸಬಹುದು, ಮತ್ತು ನೀವು IoT ಸಂದೇಶಗಳಿಗೆ ಪ್ರತಿಕ್ರಿಯಿಸುವ ಕೋಡ್ ಬರೆಯಲು ಹಾಗೂ ಅದನ್ನು ಸ್ಥಳೀಯವಾಗಿ ಕಾರ್ಯಗತಗೊಳಿಸಬಹುದು. ನೀವು ನಿಮ್ಮ ಕೋಡ್ ಅನ್ನು ಡಿಬಗ್ಗೊಳಿಸಲು ಸಹ ಸಾಧ್ಯ. ನಿಮ್ಮ ಕೋಡ್ ತೃಪ್ತಿದಾಯಕವಾಗಿದ್ರೆ ಅದನ್ನು ನಂತರ ಕ್ಲೌಡ್ ಗೆ ನಿಯೋಜಿಸಬಹುದು.

Azure Functions ಉಪಕರಣ CLI ಆಗಿ ಲಭ್ಯವಿದೆ, ಅದು Azure Functions Core Tools ಎಂದು ಕರೆಯಲ್ಪಡುತ್ತದೆ.

1. [Azure Functions Core Tools ಡಾಕ್ಯುಮೆಂಟೇಶನ್](https://docs.microsoft.com/azure/azure-functions/functions-run-local?WT.mc_id=academic-17441-jabenn) ನಲ್ಲಿ ಸೂಚನೆಗಳನ್ನು ಅನುಸರಿಸಿ Azure Functions ಕೋರ್ ಟೂಲ್ಸ್ ಅನ್ನು ಸ್ಥಾಪಿಸಿ

1. VS ಕೋಡ್ ಗೆ Azure Functions\Extension ಅನ್ನು ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಿ. ಈ\Extension ಅನ್ನು Functions ರಚನೆ, ಡಿಬಗ್ಗಿಂಗ್ ಮತ್ತು ನಿಯೋಜನೆಗೆ ಬೆಂಬಲ ನೀಡುತ್ತದೆ. ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಲು [Azure Functions\Extension ಡಾಕ್ಯುಮೆಂಟೇಶನ್](https://marketplace.visualstudio.com/items?WT.mc_id=academic-17441-jabenn&itemName=ms-azuretools.vscode-azurefunctions) ನೋಡಿ.

ನೀವು ನಿಮ್ಮ Azure Functions ಆ್ಯಪ್ ಅನ್ನು ಕ್ಲೌಡ್ ಗೆ ನಿಯೋಜಿಸಿದಾಗ, ಅವು ಅಪ್ಲಿಕೇಶನ್ ಫೈல்கள் ಮತ್ತು ಲಾಗ್ ಫೈಲ್‌ಗಳನ್ನು ಸಂಗ್ರಹಿಸಲು ಸ್ವಲ್ಪ ಕ್ಲೌಡ್ ಸ್ಟೋರೇಜ್ ಬಳಸುತ್ತಾರೆ. ನೀವು ನಿಮ್ಮ Functions ಆ್ಯಪ್ ಅನ್ನು ಸ್ಥಳೀಯವಾಗಿ ಚಾಲನೆ ಮಾಡಿದಾಗಲೂ, ಕ್ಲೌಡ್ ಸ್ಟೋರೇಜ್ ಗೆ ಸಂಪರ್ಕ ಹೊಂದಬೇಕಾಗುತ್ತದೆ, ಆದರೆ ನಿಜವಾದ ಕ್ಲೌಡ್ ಸ್ಟೋರೇಜ್ ಬಳಸದಿದ್ದೂ `Azurite` ಎಂದು ಕರೆಯುವ ಸ್ಟೋರೇಜ್ ಎಮ್ಯುಲೇಟರ್ ಬಳಸಬಹುದು. ಇದು ಸ್ಥಳೀಯವಾಗಿ ಓಡುತ್ತದೆ ಆದರೆ ಕ್ಲೌಡ್ ಸ್ಟೋರೇಜ್ ಎಂಬಂತೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ.

> 🎓 ಅಜೂರ್‌ನಲ್ಲಿ, Azure Functions uses an Azure Storage Account. ಈ ಖಾತೆಗಳು ಫೈಲ್ಗಳು, ಬ್ಲಾಬ್ಸ್, ಟೇಬಲ್‌ಗಳಲ್ಲಿ ಡೇಟಾ ಅಥವಾ ಕ್ಯೂ ಗಳು ಮೊದಲಾದ ಡೇಟಾ ಸಂಗ್ರಹಿಸಬಹುದು. ನೀವು ಹಲವಾರು ಆ್ಯಪ್ ಗಳ ನಡುವೆ ಒಂದು ಸ್ಟೋರೇಜ್ ಖಾತೆಯನ್ನು ಹಂಚಿಕೊಳ್ಳಬಹುದು, ಉದಾಹರಣೆಗೆ ಒಂದು Functions ಆ್ಯಪ್ ಮತ್ತು ಒಂದು ವೆಬ್ ಆ್ಯಪ್.

1. Azurite ಒಂದು Node.js ಆ್ಯಪ್ ಆಗಿದೆ, ಆದ್ದರಿಂದ ನೀವು Node.js ಸ್ಥಾಪಿಸಬೇಕು. ಡೌನ್‌ಲೋಡ್ ಮತ್ತು ಸ್ಥಾಪನೆ ಸೂಚನೆಗಳನ್ನು [Node.js ವೆಬ್‌ಸೈಟ್](https://nodejs.org/) ನಲ್ಲಿ ಸ್ಪಷ್ಟವಾಗಿ ಕಾಣಬಹುದು. ನೀವು Mac ಬಳಸುತ್ತಿದ್ದರೆ, ನೀವು ಇದನ್ನು [Homebrew](https://formulae.brew.sh/formula/node) ಇಂದಲೂ ಸ್ಥಾಪಿಸಬಹುದು.

1. ಕೆಳಗಿನ ಆದೇಶ ಬಳಸಿಕೊಂಡು Azurite ಅನ್ನು ಸ್ಥಾಪಿಸಿ (`npm` ಎಂಬ ಉಪಕರಣವು Node.js ಸ್ಥಾಪಿಸಿದಾಗ ಲಭ್ಯವಾಗುತ್ತದೆ):

    ```sh
    npm install -g azurite
    ```

1. Azuriteಗೆ ಡೇಟಾ ಸಂಗ್ರಹಿಸಲು `azurite` ಎಂಬ ಫೋಲ್ಡರ್ ರಚಿಸಿ:

    ```sh
    mkdir azurite
    ```

1. ಈ ಹೊಸ ಫೋಲ್ಡರ್ ಅನ್ನು Azurite ಗೆ ನೀಡಿ ಚಾಲನೆ ಮಾಡಿ:

    ```sh
    azurite --location azurite
    ```

    Azurite ಸ್ಟೋರೇಜ್ ಎಮ್ಯುಲೇಟರ್ ಪ್ರಾರಂಭವಾಗುತ್ತದೆ ಮತ್ತು ಸ್ಥಳೀಯ Functions ರನ್ ಟೈಮ್ ಗೆ ಸಂಪರ್ಕಕ್ಕೆ ಸಿದ್ಧವಾಗುತ್ತದೆ.

    ```output
    ➜  ~ azurite --location azurite  
    Azurite Blob service is starting at http://127.0.0.1:10000
    Azurite Blob service is successfully listening at http://127.0.0.1:10000
    Azurite Queue service is starting at http://127.0.0.1:10001
    Azurite Queue service is successfully listening at http://127.0.0.1:10001
    Azurite Table service is starting at http://127.0.0.1:10002
    Azurite Table service is successfully listening at http://127.0.0.1:10002
    ```

### ಕಾರ್ಯ - Azure Functions ಪ್ರಾಜೆಕ್ಟ್ ರಚಿಸಿ

Azure Functions CLI ಮೂಲಕ ಹೊಸ Functions ಆ್ಯಪ್ ರಚಿಸಬಹುದು.

1. ನಿಮ್ಮ Functions ಆ್ಯಪ್ ಗೆ ಒಂದು ಫೋಲ್ಡರ್ ರಚಿಸಿ ಮತ್ತು ಅದರಲ್ಲಿ ಹೋಗಿ. ಹೆಸರನ್ನು `soil-moisture-trigger` ಎಂದು ಇರಿಸಿ

    ```sh
    mkdir soil-moisture-trigger
    cd soil-moisture-trigger
    ```

1. ಈ ಫೋಲ್ಡರ್ ಒಳಗೆ Python ವರ್ಚುವಲ್ ಎನ್ವಿರಾನ್ಮೆಂಟ್ ಸೃಷ್ಟಿಸಿ:

    ```sh
    python3 -m venv .venv
    ```

1. ವರ್ಚುವಲ್ ಎನ್ವಿರಾನ್ಮೆಂಟ್ ಸಕ್ರಿಯಗೊಳಿಸಿ:

    * Windows ನಲ್ಲಿ:
        * ನೀವು Command Prompt ಅಥವಾ Command Prompt through Windows Terminal ಬಳಸುತ್ತಿದ್ದರೆ, ಈ ಆದೇಶ ಅನ್ನು ಚಲಾಯಿಸಿ:

            ```cmd
            .venv\Scripts\activate.bat
            ```

        * ನೀವು PowerShell ಬಳಸುತ್ತಿದ್ದರೆ, ಈ ಆದೇಶವನ್ನು ಚಲಾಯಿಸಿ:

            ```powershell
            .\.venv\Scripts\Activate.ps1
            ```

    * macOS ಅಥವಾ Linux ನಲ್ಲಿ, ಈ ಆದೇಶವನ್ನು ಚಲಾಯಿಸಿ:

        ```cmd
        source ./.venv/bin/activate
        ```

    > 💁 ಈ ಆದೇಶಗಳನ್ನು ನೀವು ವರ್ಚುವಲ್ ಎನ್ವಿರಾನ್ಮೆಂಟ್ ರಚಿಸಿದ ಸ್ಥಳದಿಂದಲೇ ಚಲಾಯಿಸಬೇಕು. `.venv` ಫೋಲ್ಡರ್ ಒಳಗೆ ಹೋಗಬೇಕಾಗಿಲ್ಲ, ನೀವು ಯಾವಾಗಲೂ ಸಕ್ರಿಯಗೊಳಿಸುವ ಆದೇಶವನ್ನು ಮತ್ತು ಪ್ಯಾಕೇಜ್‌ಗಳನ್ನು ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡುವ ಅಥವಾ ಕೋಡ್ ಓಡಿಸುವ ಆದೇಶಗಳನ್ನು ನೀವು ತಯಾರಿಸಿದ ಸ್ಥಳದಿಂದಲೇ ಚಲಾಯಿಸಬೇಕು.

1. ಈ ಫೋಲ್ಡರ್ ನಲ್ಲಿ Functions ಆ್ಯಪ್ ರಚಿಸಲು ಕೆಳಗಿನ ಆದೇಶವನ್ನು ಚಲಾಯಿಸಿ:

    ```sh
    func init --worker-runtime python soil-moisture-trigger
    ```

    ಇದು ಪ್ರಸ್ತುತ ಫೋಲ್ಡರ್ ಒಳಗೆ ಮೂರು ಫೈಲ್ ಗಳನ್ನು ರಚಿಸುತ್ತದೆ:

    * `host.json` - ಈ JSON ಪೊರೆಗೆ Functions ಆ್ಯಪ್ ಗೆ ಸಂರಚನೆ ಇದೆ. ನೀವು ಇದನ್ನು ಬದಲಿಸಲು ಅಗತ್ಯವಿಲ್ಲ.
    * `local.settings.json` - ಈ JSON ಆಪ್ತೋಪೇಕ್ಷಿತವಾಗಿ ಸ್ಥಳೀಯವಾಗಿ ರನ್ನಿಂಗ್ ಸಮಯದಲ್ಲಿ ಬಳಸುವ ಸಂರಚನೆಗಳನ್ನು ಹೊಂದಿದೆ, ಉದಾ: ನಿಮ್ಮ IoT Hub ಕನೆಕ್ಷನ್ ಸ್ಟ್ರಿಂಗ್. ಈ ಸಂರಚನೆಗಳು ಸ್ಥಳೀಯ ಮಾತ್ರ, ಮತ್ತು ಸೋರ್ಸ್ ಕಂಟ್ರೋಲ್ ಗೆ ಸೇರಿಸಲಾಗಬಾರದು. ನಿಮ್ಮ ಆ್ಯಪ್ ಕ್ಲೌಡ್ ಗೆ ನಿಯೋಜಿಸಿದಾಗ, ಈ ಸಂರಚನೆಗಳು ನಿಯೋಜಿಸಲ್ಪಡುವುದಿಲ್ಲ, ಬದಲಿಗೆ ನೀವು ಅಪ್ಲಿಕೇಶನ್ ಸೆಟ್ಟಿಂಗ್ ಗಳಿಂದ ಸಂರಚನೆಯನ್ನು ಬಳಸುತ್ತೀರಿ. ಈ ವಿಷಯವನ್ನು ನಂತರ ಕಾಣಲಾಗುವುದು.
    * `requirements.txt` - ಇದು [Pip requirements ಫೈಲ್](https://pip.pypa.io/en/stable/user_guide/#requirements-files), ಈ ಫೈಲ್ ನಲ್ಲಿ ನಿಮಗೆ ಬೇಕಾದ ಪಿಪ್ ಪ್ಯಾಕೇಜ್ ಗಳ ವಿಷಯವಿರುತ್ತದೆ.

1. `local.settings.json` ಫೈಲ್ ನಲ್ಲಿ Functions ಆ್ಯಪ್ ಅದನ್ನು ಬಳಸುವ ಸ್ಟೋರೇಜ್ ಖಾತೆಗಾಗಿ ಸೆಟ್ಟಿಂಗ್ ಇದೆ. ಇದು ಖಾಲಿಯಾಗಿರುತ್ತದೆ ಹಾಗಾಗಿ ಇದನ್ನು ಹೊಂದಿಸುವ ಅಗತ್ಯವಿದೆ. Azurite ಸ್ಥಳೀಯ ಡೇಟಾ ಸಂಗ್ರಹಣೆ ಎಮ್ಯುಲೇಟರ್ ಗೆ ಸಂಪರ್ಕಿಸಲು ಈ ಮೌಲ್ಯವನ್ನು ನೀವು ಈ ಕೆಳಗಿನಂತೆ ಹೊಂದಿಸಿ:

    ```json
    "AzureWebJobsStorage": "UseDevelopmentStorage=true",
    ```

1. ಅಗತ್ಯವಾದ ಪಿಪ್ ಪ್ಯಾಕೇಜ್ ಗಳನ್ನು requirements ಫೈಲ್ ಮೂಲಕ ಸ್ಥಾಪಿಸಿ:

    ```sh
    pip install -r requirements.txt
    ```

    > 💁 ಕಾಮಗಾರಿ ಸಮಯದಲ್ಲಿ Functions ಆ್ಯಪ್ ಕ್ಲೌಡ್ ಗೆ ನಿಯೋಜಿತವಾಗುವಾಗ, ರನ್ ಟೈಮ್ ಸರಿಯಾದ ಪ್ಯಾಕೇಜುಗಳನ್ನು ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡುವುದಕ್ಕಾಗಿ ಈ ಫೈಲ್ ಅಗತ್ಯ.

## IoT ಹಬ್ ಘಟನಾ ಟ್ರಿಗರ್ ರಚಿಸಿ

Functions ಅಪ್ಲಿಕೇಶನ್ ನಿಮ್ಮ ಸರ್ವರ್‍ಲೆಸ್ ಕೋಡಿನ ಶೆಲ್ ಆಗಿದೆ. IoT ಹಬ್ ಘಟನೆಗಳಿಗೆ ಪ್ರತಿಕ್ರಿಯಿಸಲು, ನೀವು ಈ ಅಪ್ಲಿಕೇಶನ್‌ಗೆ IoT ಹಬ್ ಟ್ರಿಗರ್ ಅನ್ನು ಸೇರಿಸಬಹುದು. ಈ ಟ್ರಿಗರ್ IoT ಹಬ್‌ಗೆ ಕಳುಹಿಸಲಾದ ಸಂದೇಶಗಳ ಸ್ಟ್ರೀಮ್‌ಗೆ ಸಂಪರ್ಕಿಸುವ ಅಗತ್ಯವಿದೆ ಮತ್ತು ಅದಕ್ಕೆ ಪ್ರತಿಕ್ರಿಯಿಸಬೇಕು. ಈ ಸಂದೇಶಗಳ ಸ್ಟ್ರೀಮ್ ಪಡೆಯಲು, ನಿಮ್ಮ ಟ್ರಿಗರ್ IoT ಹಬ್ಬಿನ *ಘಟನಾ ಹಬ್ ಹೊಂದಿಕೆಯಾಗುವ ಕೊನೇ ಬಿಂದು*ಗೆ ಸಂಪರ್ಕಿಸುವ ಅಗತ್ಯವಿದೆ.

IoT ಹಬ್ ಇನ್ನೊಂದು ಆಜೂರ್ ಸೇವೆಯಾಗಿರುವ ಆಜೂರ್ ಈವೆಂಟ್ ಹಬ್ಬ್ ಮೇಲೆ ಆಧಾರಿತವಾಗಿದೆ. ಈವೆಂಟ್ ಹಬ್ಬ್是一种允许您发送和接收消息的服务，IoT Hub则扩展此服务以针对物联网设备提供额外功能。读取IoT Hub消息的方式与使用事件中心相同。

✅ ಸ್ವಲ್ಪ ಸಂಶೋಧನೆ ಮಾಡಿ: [Azure Event Hubs ಡಾಕ್ಯುಮೆಂಟೇಶನ್](https://docs.microsoft.com/azure/event-hubs/event-hubs-about?WT.mc_id=academic-17441-jabenn) ನಲ್ಲಿ ಈವೆಂಟ್ ಹಬ್ಬ್ಗಳ ಅವಲೋಕನ ಓದಿ. ಮೂಲಭೂತ ವೈಶಿಷ್ಟ್ಯತೆಗಳು IoT ಹಬ್ ಜೊತೆಗೆ ಹೇಗೆ ಹೋಲುತ್ತಾರೆ?

ಒಂದು IoT ಸಾಧನ IoT ಹಬ್‌ಗೆ ಸಂಪರ್ಕಿಸಲು, ಅದು ಕೇವಲ ಅನುಮತಿಪಡಿಸಲಾದ ಸಾಧನಗಳಿಗೆ ಮಾತ್ರ ಸಂಪರ್ಕ ಇಲ್ಲವೆಂದೇ ಖಚಿತಪಡಿಸಲು ಹೀಗೊಂದು ಗುಪ್ತ ಕೀಲಿಯನ್ನು ಬಳಸಬೇಕು. ಸಂದೇಶಗಳನ್ನು ಓದುವಾಗ ಸಂಪರ್ಕಿಸುವಾಗವೂ ಇದೇ ನಿಯಮ ಅನ್ವಯಿಸುತ್ತದೆ, ನೀವು ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ ಬೇಕಾಗುತ್ತದೆ ಇದು ಗುಪ್ತ ಕೀಲಿಯನ್ನು ಒಳಗೊಂಡಿರಬೇಕು ಮತ್ತು IoT ಹಬ್ ವಿವರಗಳನ್ನೂ ಒಳಗೊಂಡಿರಬೇಕು.

> 💁 ನೀವು ಪಡೆದ ಡೀಫಾಲ್ಟ್ ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ **iothubowner** ಅನುವುಗಳನ್ನು ಹೊಂದಿದೆ, ಇದು ಅದನ್ನು ಬಳಸುವ ಯಾವುದೇ ಕೋಡ್‌ಗೆ IoT ಹಬ್ಬಿನ ಪೂರ್ಣ ನಿರ್ವಾಹಕರ ಅನುವುಗಳನ್ನು ನೀಡುತ್ತದೆ. ಆದರ್ಶವಾಗಿ ನೀವು ಅತ್ಯಲ್ಪ ಮಟ್ಟಿನ ಅನುವುಗಳನ್ನು ಹೊಂದಿದ ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ ಬಳಸಿ ಸಂಪರ್ಕ ಮಾಡಬೇಕು. ಇದು ಮುಂದಿನ ಪಾಠದಲ್ಲಿ ವಿವರಿಸಲಾಗುತ್ತದೆ.

ನಿಮ್ಮ ಟ್ರಿಗರ್ ಅನ್ನು ಸಂಪರ್ಕಿಸಿದ ಬಳಿಕ, ಫಂಕ್ಷನ್ ಒಳಗಿನ ಕೋಡ್ ಪ್ರತಿಯೊಂದು IoT ಹಬ್ಬಿಗೆ ಕಳುಹಿಸಲಾದ ಸಂದೇಶಕ್ಕೂ ಕರೆಮಾಡಲಾಗುತ್ತದೆ, ಯಾವುದಾದರೂ ಸಾಧನದಿಂದ ಕಳುಹಿಸಲಾದುದೇ ಆಗಿರಲಿ. ಟ್ರಿಗರ್‌ಗೆ ಆ ಸಂದೇಶವು ಪ್ಯಾರಾಮೀಟರ್ ಆಗಿ ನೀಡಲಾಗುತ್ತದೆ.

### ಕಾರ್ಯ - ಈವೆಂಟ್ ಹಬ್ ಹೊಂದಿಕೆಯಾಗುವ ಕೊನೇ ಬಿಂದುವಿನ ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ ಪಡೆಯಿರಿ

1. VS Code ಟರ್ಮಿನಲ್‌ನಿಂದ ಕೆಳಗಿನ ಕಮಾಂಡ್ ಅನ್ನು ಚಲಿಸಿ IoT ಹಬ್ಬಿನ ಈವೆಂಟ್ ಹಬ್ ಹೊಂದಿಕೆಯಾಗುವ ಕೊನೇ ಬಿಂದುಗೆ ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ ಪಡೆಯಿರಿ:

    ```sh
    az iot hub connection-string show --default-eventhub \
                                      --output table \
                                      --hub-name <hub_name>
    ```

    `<hub_name>` ಅನ್ನು ನಿಮ್ಮ IoT ಹಬ್ಬಿನ ಹೆಸರಿನಿಂದ ಬದಲಾಯಿಸಿ.

1. VS Code ನಲ್ಲಿ `local.settings.json` ಫೈಲ್ ತೆರೆಯಿರಿ. `Values` ವಿಭಾಗದೊಳಗೆ ಕೆಳಗಿನ ಹೆಚ್ಚುವರಿ ಮೌಲ್ಯ ಅನ್ನು ಸೇರಿಸಿ:

    ```json
    "IOT_HUB_CONNECTION_STRING": "<connection string>"
    ```

    `<connection string>` ಅನ್ನು ಮುಂಚಿನ ಹಂತದಿಂದ ಪಡೆದ ಮೌಲ್ಯದಿಂದ ಬದಲಾಯಿಸಿ. ಈ ನೀವು ಸರಿಯಾದ JSON ಆಗಲು ಮೊದಲ ಸಾಲಿನ ನಂತರ ಕೋಮಾ ಸೇರಿಸುವ ಅಗತ್ಯ ಮಾಡಿಕೊಳ್ಳಿ.

### ಕಾರ್ಯ - ಈವೆಂಟ್ ಟ್ರಿಗರ್ ರಚಿಸಿ

ನೀವು ಈಗ ಈವೆಂಟ್ ಟ್ರಿಗರ್ ರಚಿಸಲು ಸಿದ್ಧರಾಗಿದ್ದೀರಿ.

1. VS Code ಟರ್ಮಿನಲ್‌ನಿಂದ `soil-moisture-trigger` ಫೋಲ್ಡರ್ ಒಳಗೆ ಕೆಳಗಿನ ಕಮಾಂಡ್ ಅನ್ನು ಚಾಲನೆ ಮಾಡಿ:

    ```sh
    func new --name iot-hub-trigger --template "Azure Event Hub trigger"
    ```

    ಇದು `iot-hub-trigger` ಎನ್ನುವ ಹೊಸ ಫಂಕ್ಷನ್ ಸೃಷ್ಟಿಸುತ್ತದೆ. ಟ್ರಿಗರ್ IoT ಹಬ್ಬಿನ ಈವೆಂಟ್ ಹಬ್ ಹೊಂದಿಕೊಳ್ಳುವ ಕೊನೇ ಬಿಂದುವಿಗೆ ಸಂಪರ್ಕಿಸಿ, ನೀವು ಈವೆಂಟ್ ಹಬ್ ಟ್ರಿಗರ್ ಬಳಸಿ ಫಂಕ್ಷನ್ ರಚಿಸಬಹುದು. ವಿಶೇಷ IoT ಹಬ್ ಟ್ರಿಗರ್ ಇಲ್ಲ.

ಇದು `soil-moisture-trigger` ಫೋಲ್ಡರ್‌ಒಳಗೆ `iot-hub-trigger` ಎನ್ನುವ ಫೋಲ್ಡರ್ ರಚಿಸುತ್ತದೆ ಮತ್ತು ಆ ಫೋಲ್ಡರ್ ಈ ಫಂಕ್ಷನ್ ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ. ಈ ಫೋಲ್ಡರ್‌ಗೆ ಕೆಳಗಿನ ಫೈಲ್‌ಗಳು ಇರಬಹುದು:

* `__init__.py` - ಈ ಪೈಥಾನ್ ಕೋಡ್ ಫೈಲ್ ಆಗಿದ್ದು, ಈ ಟ್ರಿಗರ್ ಅನ್ನು ಒಳಗೊಂಡಿದೆ ಮತ್ತು ಮಾನ್ಯ ಪೈಥಾನ್ ಫೈಲ್ ಹೆಸರಿನ ಸಂಪ್ರದಾಯವನ್ನು ಬಳಸಿಕೊಂಡು ಈ ಫೋಲ್ಡರ್ ಅನ್ನು ಪೈಥಾನ್ ಮೋಡ್ಯೂಲ್ ಆಗಿ ಮಾಡಿ.

    ಈ ಫೈಲ್ ಕೆಳಗಿನ ಕೋಡ್ ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ:

    ```python
    import logging

    import azure.functions as func


    def main(event: func.EventHubEvent):
        logging.info('Python EventHub trigger processed an event: %s',
                    event.get_body().decode('utf-8'))
    ```

    ಟ್ರಿಗರ್ ಕೋರ್ ಆಗಿರುವುದು `main` ಫಂಕ್ಷನ್. IoT ಹಬ್ಬಿನ ಘಟನೆಗಳಿಂದ ಈ ಫಂಕ್ಷನ್ ಕರೆಯಲಾಗುತ್ತದೆ. ಈ ಫಂಕ್ಷನ್ `event` ಎಂಬ ಪ್ಯಾರಾಮೀಟರ್ ಹೊಂದಿದೆ ಇದರಲ್ಲಿ `EventHubEvent` ಇದೆ. ಪ್ರತಿಯೊಂದು ವೇಳೆ IoT ಹಬ್ಬಿಗೆ ಸಂದೇಶ ಕಳುಹಿಸುವಾಗ, ಈ ಫಂಕ್ಷನ್ `event` ಆಗಿ ಸಂದೇಶವು, ಅದರ ಜೊತೆಗೆ ಈ ಹಿಂದೆ ನೀವು ನೋಡಿದ ಟಿಪ್ಪಣಿಗಳಂತೆ ವೈಶಿಷ್ಟ್ಯಗಳು ಕೂಡಾ saamILLge ಕಳುಹಿಸಲಾಗುತ್ತವೆ.

    ಈ ಫಂಕ್ಷನ್ ಕೋರ್ ಘಟನೆಗಳನ್ನು ಲಾಗ್ ಮಾಡುತ್ತದೆ.

* `function.json` - ಈ ಫೈಲ್ ಟ್ರಿಗರ್ ಇನ್ಪುಟ್ ಕಾಂಫಿಗರೇಶನ್ ಹೊಂದಿದೆ. ಪ್ರಮುಖ ಕಾಂಫಿಗರೇಶನ್ `bindings` ವಿಭಾಗದಲ್ಲಿ ಇರುತ್ತದೆ. ಬಿಂಗಿಂಗ್ ಎಂದರೆ ಆಜೂರ್ ಫಂಕ್ಷನ್ಸ್ ಮತ್ತು ಇತರ ಆಜೂರ್ ಸೇವೆಗಳ ನಡುವೆ ಸಂಪರ್ಕವನ್ನು ಸೂಚಿಸುತ್ತದೆ. ಈ ಫಂಕ್ಷನ್ ಒಂದಿಷ್ಟು ಬಿನ್ನಾಯ್ ಹೊಂದಿದೆ, ಅದು ಒಂದು ಇವೆಂಟ್ ಹಬ್ ನಿಂದ ಡೇಟಾಬಂದಿ ಪಡೆಯುತ್ತದೆ.

    > 💁 ನೀವು ಔಟ್ ಪುಟ್ ಬಿನ್ನಾಯಿ ಕೂಡ ಇರಿಸಬಹುದು, ಉದಾಹರಣೆಗೆ ನೀವು ಡೇಟಾಬೇಸ್‌ಗೆ ಔಟ್ ಪುಟ್ ಬಿನ್ನಾಯ್ ಸೇರಿಸಿ IoT ಹಬ್ ಘಟನೆ ಫಂಕ್ಷನ್‌ನಿಂದ ರಿಟರ್ನ್ ಮಾಡಿ ಡೇಟಾಬೇಸ್‌ಗೆ ಸ್ವಯಂಚಾಲಿತ ಸೇರಿಸುವುದನ್ನು ಮಾಡಬಹುದು.

    ✅ ಸ್ವಲ್ಪ ಸಂಶೋಧನೆ ಮಾಡಿ: [Azure Functions ಟ್ರಿಗರ್‌ಗಳು ಮತ್ತು ಬಿನ್ನಾಯಿಗಳು ಸಮ್Concepts ಡಾಕ್ಯುಮೆಂಟೇಶನ್](https://docs.microsoft.com/azure/azure-functions/functions-triggers-bindings?WT.mc_id=academic-17441-jabenn&tabs=python) ಓದಿ.

    `bindings` ವಿಭಾಗದಲ್ಲಿ ಕೆಳಗಿನ ಪ್ರಮುಖ ವಿಡ್ರತೆಗಳಿವೆ:

  * `"type": "eventHubTrigger"` - ಈ ಫಂಕ್ಷನ್ ಈವೆಂಟ್ ಹಬ್ಬಿನಿಂದ ಈವೆಂಟ್ಗಳು ಬರುವುದನ್ನು ತಿಳಿಯುತ್ತದೆ
  * `"name": "events"` - ಇದು ಈವೆಂಟ್ ಹಬ್ ಘಟನಗಳ ಪ್ಯಾರಾಮೀಟರ್ ಹೆಸರು, ಇದು ಪೈಥಾನ್ ಕೋಡ್‍ನ `main` ಫಂಕ್ಷನ್‍ನ ಪ್ಯಾರಾಮೀಟರ್ ಹೆಸರಿನೊಂದಿಗೆ ಹೊಂದಿಕೊಳ್ಳುತ್ತದೆ
  * `"direction": "in"` - ಇದು ಇನ್ಪುಟ್ ಬಿನ್ನಾಯ್ ಆಗಿದ್ದು, ಈವೆಂಟ್ ಹಬ್ಬಿನಿಂದ ಡೇಟಾ ಬರುತ್ತದೆ
  * `"connection": ""` - ಈ ಸ್ಟ್ರಿಂಗ್ ಇದನ್ನು `local.settings.json` ಫೈಲ್‌ನಲ್ಲಿ ಡೇಟಾ ಓದಲು ಬಳಸುವ ಸೆಟ್ಟಿಂಗ್ ವಸ್ತು ಹೆಸರನ್ನು ಸೂಚಿಸುತ್ತದೆ.

    > 💁 ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ `function.json` ಫೈಲ್‌ನಲ್ಲಿ ಇರಿಸಲಾಗುವುದಿಲ್ಲ, ಇದು ನಿಮ್ಮ ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ ಅನ್ನು ಅನಿರೀಕ್ಷಿತವಾಗಿ ಬಹಿರಂಗಪಡಿಸುವುದನ್ನು ತಡೆಯಲು.

1. [Azure Functions ಟೆಂಪ್ಲೇಟ್ನಲ್ಲಿನ ಬગ್](https://github.com/Azure/azure-functions-templates/issues/1250) ಕಾರಣದಿಂದ `function.json` ನಲ್ಲಿ `cardinality` ಕ್ಷೇತ್ರದ ಮೌಲ್ಯ ತಪ್ಪಿದೆ. ಈ ಮೌಲ್ಯವನ್ನು `many` ರಿಂದ `one` ಗೆ ಬದಲಾಯಿಸಿ:

    ```json
    "cardinality": "one",
    ```

1. `function.json` ಫೈಲ್‌ನಲ್ಲಿ `"connection"` ಮೌಲ್ಯವನ್ನು `local.settings.json` ಫೈಲ್‌ನ ಹೊಸ ಸೆಟ್ಟಿಂಗ್‌ಗೆ ಸೂಚಿಸುವಂತೆ ಬದಲಾಯಿಸಿ:

    ```json
    "connection": "IOT_HUB_CONNECTION_STRING",
    ```

    > 💁 ನೆನಪಿಡಿ - ಇದು ಸೆಟ್ಟಿಂಗ್ ಅನ್ನು ಸೂಚಿಸಬೇಕು, ನಿಜವಾದ ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ ಇರಕೂಡದು.

1. ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ ನಲ್ಲಿ `eventHubName` ಮೌಲ್ಯವಿದೆ, ಆದ್ದರಿಂದ `function.json` ಫೈಲ್‌ನ ಆ ಮೌಲ್ಯವನ್ನು ಖಾಲಿ ಸ್ಟ್ರಿಂಗ್ ಗಾಗಿ ಬದಲಾಯಿಸಬೇಕು:

    ```json
    "eventHubName": "",
    ```

## ಸರ್ವರ್‍ಲೆಸ್ ಕೋಡ್ ನಿಂದ ನೇರ ರೀತಿಯ ಕಮಾಂಡ್ ಕಳುಹಿಸಿ

ಇದುವರೆಗೆ ನಿಮ್ಮ Functions ಅಪ್ಲಿಕೇಶನ್ Event Hub ಹೊಂದಿಕೆಯಾಗುವ ಕೊನೆಯೃಂದಿನಿಂದ IoT ಹಬ್ಬಿನ ಸಂದೇಶಗಳನ್ನು ಕೇಳುತ್ತಿದೆ. ಈಗ ನೀವು IoT ಸಾಧನಕ್ಕೆ ಕಮಾಂಡ್ ಕಳುಹಿಸಬೇಕು. ಇದು *Registry Manager* ಮೂಲಕ ವೈಯಕ್ತಿಕ IoT ಹಬ್ ಗೆ ಸಂಪರ್ಕಿಸುವ ಬೇರೊಂದು ಸಂಪರ್ಕವನ್ನು ಬಳಸುವ ಮೂಲಕ ಮಾಡಲಾಗುತ್ತದೆ. Registry Manager sebuah alat yang memungkinkan Anda melihat perangkat yang terdaftar di IoT Hub, berkomunikasi dengan perangkat tersebut dengan mengirim pesan dari cloud ke perangkat, permintaan metode langsung, atau memperbarui perangkat kembarannya. Anda juga dapat menggunakannya untuk mendaftarkan, memperbarui, atau menghapus perangkat IoT dari IoT Hub.

Registry Manager ಗೆ ಸಂಪರ್ಕಿಸಲು, ನಿಮಗೆ ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ ಬೇಕಾಗುತ್ತದೆ.

### ಕಾರ್ಯ - Registry Manager ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ ಪಡೆಯಿರಿ

1. ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ ಪಡೆಯಲು, ಕೆಳಗಿನ ಕಮಾಂಡ್ ಚಾಲನೆ ಮಾಡಿ:

    ```sh
    az iot hub connection-string show --policy-name service \
                                      --output table \
                                      --hub-name <hub_name>
    ```

    `<hub_name>` ಅನ್ನು ನೀವು ಬಳಸಿದ IoT ಹಬ್ ಹೆಸರಿನಿಂದ ಬದಲಾಯಿಸಿ.

    ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ `--policy-name service` ಇರುವ *ServiceConnect* ನೀತಿಯಲ್ಲ್ದಿಂದ ಕೇಳಲಾಗುತ್ತದೆ. ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್ ಕೇಳುವಾಗ, ನೀವು ಹಿಂದೆav电影 ಅದೊಂದು ಅನುಮತಿ ಮಾಡುತ್ತದೆ ಎಂದು ಸೂಚಿಸಬಹುದು. ServiceConnect ನೀತಿ ನಿಮ್ಮ ಕೋಡ್‌ಗೆ IoT ಸಾಧನಗಳಿಗೆ ಸಂಪರ್ಕ ಮಾಡಿಸಿ ಮತ್ತು ಸಂದೇಶ ಕಳುಹಿಸಲು ಅನುಮತಿಸುತ್ತದೆ.

    ✅ ಸ್ವಲ್ಪ ಸಂಶೋಧನೆ ಮಾಡಿ: [IoT Hub ಅನುಮತಿಯ ಡಾಕ್ಯುಮೆಂಟೇಶನ್](https://docs.microsoft.com/azure/iot-hub/iot-hub-devguide-security#iot-hub-permissions?WT.mc_id=academic-17441-jabenn) ನಲ್ಲಿ ವಿಭಿನ್ನ ನೀತಿಗಳನ್ನು ಓದಿ.

1. VS Code ನಲ್ಲಿ `local.settings.json` ಫೈಲ್ ತೆರೆಯಿರಿ. `Values` ವಿಭಾಗದಲ್ಲಿ ಕೆಳಗಿನ ಹೆಚ್ಚುವರಿ ಮೌಲ್ಯ ಸೇರಿಸಿ:

    ```json
    "REGISTRY_MANAGER_CONNECTION_STRING": "<connection string>"
    ```

    `<connection string>` ಅನ್ನು ಹಿಂದಿನ ಹಂತದಿಂದ ಪಡೆದ ಮೌಲ್ಯದಿಂದ ಬದಲಾಯಿಸಿ. ಸರಿಯಾದ JSON ಆಗಿರಲು ಮೇಲಿನ ಸಾಲಿನ ನಂತರ ಕೋಮಾ ಸೇರಿಸುವ ಅಗತ್ಯವಿದೆ.

### ಕಾರ್ಯ - ಸಾಧನಕ್ಕೆ ನೇರ ರೀತಿಯ ಕಮಾಂಡ್ ಕಳುಹಿಸಿ

1. Registry Manager SDK Pip ಪ್ಯಾಕೇಜ್ ಮೂಲಕ ಲಭ್ಯವಿದೆ. ಈ ಪ್ಯಾಕೇಜ್ ಅನ್ನು ಅವಲಂಬನೆಗೆ ಸೇರಿಸಲು `requirements.txt` ಫೈಲ್‌ಗೆ ಕೆಳಗಿನ ಸಾಲು ಸೇರಿಸಿ:

    ```sh
    azure-iot-hub
    ```

1. VS Code ಟರ್ಮಿನಲ್‌ನಲ್ಲಿ ವರ್ಚುಯಲ್ ಎನ್ವಿರಾನ್ಮೆಂಟ್ ಸಕ್ರಿಯವಿದ್ದು ಅನ್ನು ಖಚಿತಪಡಿಸಿ, ಹಾಗೂ ಕೆಳಗಿನ ಕಮಾಂಡ್ ಚಲಿಸಿ Pip ಪ್ಯಾಕೇಜ್‍ಗಳನ್ನು ಸ್ಥಾಪಿಸಿ:

    ```sh
    pip install -r requirements.txt
    ```

1. `__init__.py` ಫೈಲ್‍ಗೆ ಕೆಳಗಿನ ಇಂಪೋರ್ಟ್ಗಳನ್ನು ಸೇರಿಸಿ:

    ```python
    import json
    import os
    from azure.iot.hub import IoTHubRegistryManager
    from azure.iot.hub.models import CloudToDeviceMethod
    ```

    ಇದು ಕೆಲವು ಸಿಸ್ಟಮ್ ಲೈಬ್ರರಿ ಗಳನ್ನು ಮತ್ತು Registry Manager ಜೊತೆಗೆ ನೇರ ವಿಧಾನ ಕಮಾಂಡ್ ಕಳುಹಿಸಲು ಬೇಕಾದ ಲೈಬ್ರರಿಗಳನ್ನು ಆಮದು ಮಾಡಿಕೊಳ್ಳುತ್ತದೆ.

1. `main` ಮೆಥಡ್‌ನೊಳಗಿನ ಕೋಡ್ ಅನ್ನು ತೆಗೆದುಹಾಕಿ, ಆದರೂ ಮೆಥಡ್ ಅನ್ನು ಉಳಿಸಿಕೊಂಡಿರಿ.

1. `main` ಮೆಥಡ್‌ನಲ್ಲಿ ಕೆಳಗಿನ ಕೋಡ್ ಸೇರಿಸಿ:

    ```python
    body = json.loads(event.get_body().decode('utf-8'))
    device_id = event.iothub_metadata['connection-device-id']

    logging.info(f'Received message: {body} from {device_id}')
    ```

    ಇದು ಇವೆಂಟ್‌ನ ಬಾಡಿ ಅನ್ನು ಹೊರತೆಗೆದು IoT ಸಾಧನದಿಂದ ಕಳುಹಿಸಲಾದ JSON ಸಂದೇಶವನ್ನು ಅಳವಡಿಸುತ್ತದೆ.

    ನಂತರ, ಸಂದೇಶದೊಂದಿಗೆ ಬರುವ ಟಿಪ್ಪಣಿಗಳಿಂದ ಸಾಧನ ಐಡಿ ಪಡೆಯುತ್ತದೆ. ಇವೆಂಟ್ ಬಾಡಿ ಸಂದೇಶವು ಟೆಲೆಮೆಟ್ರಿ ರೂಪದಲ್ಲಿ ಇದೆ ಮತ್ತು `iothub_metadata` ಡಿಕ್ಷನರಿಯಲ್ಲಿ IoT ಹಬ್ ನಿಂದ ಸದರಿ ಆದದ್ದ ಹೇಗಿರುತ್ತದೆ, ಉದಾಹರಣೆಗೆ ಸಾಧನ ಐಡಿ ಹಾಗೂ ಸಂದೇಶ ಕಳುಹಿಸಿದ ಸಮಯಗಳಿವೆ.

    ಈ ಮಾಹಿತಿಯನ್ನು ಟರ್ಮಿನಲ್‌ನಲ್ಲಿ ಲಾಗ್ ಮಾಡಲಾಗುತ್ತದೆ.

1. ಇದಕ್ಕೆ ಕೆಳಗೆ ಕೆಳಗಿನ ಕೋಡ್ ಸೇರಿಸಿ:

    ```python
    soil_moisture = body['soil_moisture']

    if soil_moisture > 450:
        direct_method = CloudToDeviceMethod(method_name='relay_on', payload='{}')
    else:
        direct_method = CloudToDeviceMethod(method_name='relay_off', payload='{}')
    ```

    ಇದು ಸಂದೇಶದಿಂದ ಮಣ್ಣಿನ ಆರ್ದ್ರತೆ (soil moisture) ಪಡೆಯುತ್ತದೆ. ನಂತರ ಆರ್ದ್ರತೆಯನ್ನು ಪರಿಶೀಲಿಸಿ ಮೌಲ್ಯ ಪ್ರಕಾರ `relay_on` ಅಥವಾ `relay_off` ನೇರ ಮಾರ್ಗ ವಿನಂತಿಗಾಗಿ ಸಹಾಯಕ ಕ್ಲಾಸ್ ರಚಿಸುತ್ತದೆ. ಮಾರ್ಗ ವಿನಂತಿ ಯಾವುದೇ ಪೇಲೋಡ್ ಬೇಕಾಗಿಲ್ಲ, ಆದ್ದರಿಂದ ಖಾಲಿ JSON ದಾಖಲೆ ಕಳುಹಿಸಲಾಗುತ್ತದೆ.

1. ಕೆಳಗೆ ಮತ್ತೊಂದು ಕೋಡ್ ಸೇರಿಸಿ:

    ```python
    logging.info(f'Sending direct method request for {direct_method.method_name} for device {device_id}')

    registry_manager_connection_string = os.environ['REGISTRY_MANAGER_CONNECTION_STRING']
    registry_manager = IoTHubRegistryManager(registry_manager_connection_string)
    ```

    ಇದು `local.settings.json` ಫೈಲ್‌ನಿಂದ `REGISTRY_MANAGER_CONNECTION_STRING` ಅನ್ನು ಲೋಡ್ ಮಾಡುತ್ತದೆ. ಈ ಫೈಲ್‌ನ ಮೌಲ್ಯಗಳು ಪರಿಸರ ಚರಲಿಗಳಾಗಿವೆ, ಅವನ್ನು `os.environ` ಫಂಕ್ಷನ್ ಬಳಸಿ ಓದಬಹುದು, ಇದು ಎಲ್ಲಾ ಪರಿಸರ ಚರಲಿಗಳ ಡಿಕ್ಷನರಿ ಕಳುಹಿಸುತ್ತದೆ.

    > 💁 ಈ ಕೋಡ್ ಕ್ಲೌಡ್‌ಗೆ ನಿಯೋಜಿಸಿದಾಗ, `local.settings.json` ಮೌಲ್ಯಗಳು *ಅಪ್ಲಿಕೇಶನ್ ಸೆಟ್ಟಿಂಗ್ಸ್* ಆಗಿ ಹೊಂದಿಸಿ ಅವುಗಳನ್ನು ಪರಿಸರ ಚರಲಿಗಳ ಮೂಲಕ ಓದಬಹುದು.

    ನಂತರ ಈ ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್‌ನ ಸಹಾಯದಿಂದ Registry Manager ಸಹಾಯಕರ ಕ್ಲಾಸ್‌ನ ಉದಾಹರಣೆ ಸೃಷ್ಟಿಸಿ.

1. ಕೆಳಗೆ ಮತ್ತೊಂದು ಕೋಡ್ ಸೇರಿಸಿ:

    ```python
    registry_manager.invoke_device_method(device_id, direct_method)

    logging.info('Direct method request sent!')
    ```

    ಇದು ರಿಜಿಸ್ಟ್ರಿ ಮ್ಯಾನೇಜರ್‌ಗೆ ಟೆಲಿಮೆಟ್ರಿ ಕಳುಹಿಸಿದ ಸಾಧನಕ್ಕೆ ನೇರ ಮಾರ್ಗ ವಿನಂತಿ ಕಳುಹಿಸಲು ನಮ್ಮನ್ನು ಸೂಚಿಸುತ್ತದೆ.
> 💁 ನೀವು ಮೊದಲನೇ ಪಾಠಗಳಲ್ಲಿ MQTT ಬಳಸಿಕೊಂಡು ಸೃಷ್ಟಿಸಿದ ಆ್ಯಪ್‌ನ ಆವೃತ್ತಿಗಳಲ್ಲಿ, ರಿಲೇ ನಿಯಂತ್ರಣ ಆಜ್ಞೆಗಳು ಎಲ್ಲಾ ಸಾಧನಗಳಿಗೆ ಕಳುಹಿಸಲ್ಪಟ್ಟವು. ಕೋಡ್ ನೀವು ಒಂದೇ ಸಾಧನ ಹೊಂದಿದ್ದೀರೋ ಎಂದು ಊಹಿಸಿಕೊಂಡಿತ್ತು. ಕೋಡ್‌ನ ಈ ಆವೃತ್ತಿ ವಿಧಾನ ವಿನಂತಿಯನ್ನು ಒಂದು ಸಾಧನಕ್ಕೆ ಕಳುಹಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ನೀವು ಬಹುಮಟ್ಟಿನ ತಂಪಾಗು ಸಂವೇದಕಗಳು ಮತ್ತು ರಿಲೇಗಳ ಹೊಂದಾಣಿಕೆಗಳನ್ನು ಹೊಂದಿದ್ದರೆ, ಸರಿಯಾದ ನೇರ ವಿಧಾನ ವಿನಂತಿಯನ್ನು ಸರಿಯಾದ ಸಾಧನಕ್ಕೆ ಕಳುಹಿಸುವ ಮೂಲಕ ಕೆಲಸ ಮಾಡುತ್ತದೆ.

1. ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಅನ್ನು ಚಾಲನೆ ಮಾಡಿ, ಮತ್ತು ನಿಮ್ಮ IoT ಸಾಧನ ದತ್ತಾಂಶ ಕಳುಹಿಸುತ್ತಿರುವುದನ್ನು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ. ಸಂದೇಶಗಳು ಪ್ರಕ್ರಿಯೆಗೆ ಒಳಗಾಗುತ್ತಿರುವುದನ್ನು ಮತ್ತು ನೇರ ವಿಧಾನ ವಿನಂತಿಗಳು ಕಳುಹಿಸಲ್ಪಡುತ್ತಿರುವುದನ್ನು ನೀವು ಕಾಣಬಹುದು. ಮಣ್ಣು ತಂಪಾಗು ಸಂವೇದಕವನ್ನು ಮಣ್ಣಿನ ಒಳಗೆ ಮತ್ತು ಹೊರಗೆ ಸರಿಸಿ ಮೌಲ್ಯಗಳನ್ನು ಬದಲಿಸುವುದನ್ನು ಮತ್ತು ರಿಲೇ ಆನ್ ಮತ್ತು ಆಫ್ ಆಗುವುದನ್ನು ನೋಡಿ

> 💁 ನೀವು ಈ ಕೋಡ್ ಅನ್ನು [code/functions](../../../../../2-farm/lessons/5-migrate-application-to-the-cloud/code/functions) ಫೋಲ್ಡರ್ನಲ್ಲಿ ಕಾಣಬಹುದು.

## ನಿಮ್ಮ ಸರ್ವರ್‌ಲೆಸ್ ಕೋಡ್ ಅನ್ನು ಕ್ಲೌಡ್‌ಗೆ ನಿಯೋಜಿಸು

ನಿಮ್ಮ ಕೋಡ್ ಈಗ ಸ್ಥಳೀಯವಾಗಿ ಚೆನ್ನಾಗಿಯೇ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಿದೆ, ಆದ್ದರಿಂದ ಮುಂದಿನ ಹೆಜ್ಜೆ ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಅನ್ನು ಕ್ಲೌಡ್‌ಗೆ ನಿಯೋಜಿಸುವುದು.

### ಕಾರ್ಯ - ಕ್ಲೌಡ್ ಸಂಪನ್ಮೂಲಗಳನ್ನು ಸೃಷ್ಟಿಸು

ನಿಮ್ಮ ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಅನ್ನು ನಿಮ್ಮ IoT ಹಬ್ ಗೆ ಸೃಷ್ಟಿಸಿದ ರಿಸೋರ್ಸ್ ಗುಂಪಿನೊಳಗಿನ Azure ನಲ್ಲಿ ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಸಂಪನ್ಮೂಲಕ್ಕೆ ನಿಯೋಜಿಸಬೇಕು. ಸ್ಥಳೀಯವಾಗಿ ಚಾಲನೆ ಆಗುತ್ತಿರುವ ಅನೂಕರಣ ಸಂಗ್ರಹ ಖಾತೆಯನ್ನು ಬದಲಾಯಿಸಲು Azure ನಲ್ಲಿ ಸಂಗ್ರಹ ಖಾತೆಯನ್ನು ಕೂಡ ಸೃಷ್ಟಿಸಬೇಕು.

1. ಸಂಗ್ರಹ ಖಾತೆಯನ್ನು ಸೃಷ್ಟಿಸುವುದಕ್ಕಾಗಿ ಕೆಳಗಿನ ಆಜ್ಞೆಯನ್ನು ಚಾಲನೆ ಮಾಡಿ:

    ```sh
    az storage account create --resource-group soil-moisture-sensor \
                              --sku Standard_LRS \
                              --name <storage_name> 
    ```

`<storage_name>` ಅನ್ನು ನಿಮ್ಮ ಸಂಗ್ರಹ ಖಾತೆಯ ಹೆಸರಿನಿಂದ ಬದಲಿ ಮಾಡಿ. ಇದು ಜಾಗತಿಕವಾಗಿ ವಿಶಿಷ್ಟವಾಗಿರಬೇಕು ಏಕೆಂದರೆ ಇದು ಸಂಗ್ರಹ ಖಾತೆಗೆ ಪ್ರವೇಶಿಸಲು ಬಳಸುವ URL ಭಾಗವಾಗುತ್ತದೆ. ಈ ಹೆಸರಿಗಾಗಿ ನೀವು ಕೇವಲ ಕೆಳಗಿನ ಅಕ್ಷರಗಳು ಮತ್ತು ಸಂಖ್ಯೆಗಳನ್ನು ಬಳಸಿ, ಇತರೆ ಅಕ್ಷರಗಳನ್ನು ಬಳಸಬೇಡಿ, ಮತ್ತು ಇದು 24 ಅಕ್ಷರಗಳವರೆಗೆ ಮಾತ್ರ ಇರಬಹುದು. `sms` ಅಥವಾ ಅದಕ್ಕೆ байланысты ವಿಭಿನ್ನ ID, ವಿಭಿನ್ನ ಪದಗಳು ಅಥವಾ ನಿಮ್ಮ ಹೆಸರು ಸೇರಿಸಿ ಬಳಸಬಹುದು.

`--sku Standard_LRS` ಆಯ್ಕೆ ಮೇಲ್ಮಟ್ಟದ ಬೆಲೆಯಾಗಿರುವ ಸಾಮಾನ್ಯ ಗುರಿಯ ಖಾತೆಯನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ. ಉಚಿತ ಸಂಗ್ರಹ ಸ್ಥರ ಇಲ್ಲ, ನೀವು ಬಳಕೆಮಾಡಿದಷ್ಟೇ ಪಾವತಿಸಬೇಕು. ವೆಚ್ಚಗಳು ತಗ್ಗಿವೆ, ಅತ್ಯಂತ ದುಬಾರಿ ಸಂಗ್ರಹವನ್ನು ಗಿಗಾಬೈಟ್ ಪ್ರತಿಮಹಾ US$0.05 ಕ್ಕಿಂತ ಕಡಿಮೆ ಬೆಲೆಯಾಗಿದೆ.

✅ [Azure Storage Account ಬೆಲೆಯ ಪುಟದಲ್ಲಿ](https://azure.microsoft.com/pricing/details/storage/?WT.mc_id=academic-17441-jabenn) ಬೆಲೆಯಲ್ಲಿ ಓದಿ.

1. ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಸೃಷ್ಟಿಸಲು ಕೆಳಗಿನ ಆಜ್ಞೆಯನ್ನು ಚಾಲನೆ ಮಾಡಿ:

    ```sh
    az functionapp create --resource-group soil-moisture-sensor \
                          --runtime python \
                          --functions-version 3 \
                          --os-type Linux \
                          --consumption-plan-location <location> \
                          --storage-account <storage_name> \
                          --name <functions_app_name>
    ```

`<location>` ಅನ್ನು ಹಿಂದಿನ ಪಾಠದಲ್ಲಿ ರಿಸೋರ್ಸ್ ಗುಂಪು ಸೃಷ್ಟಿಸುವಾಗ ಬಳಸಿದ ಸ್ಥಳದಿಂದ ಬದಲಿ ಮಾಡಿ.

`<storage_name>` ಅನ್ನು ಹಿಂದಿನ ಹಂತದಲ್ಲಿ ನೀವು ಸೃಷ್ಟಿಸಿದ ಸಂಗ್ರಹ ಖಾತೆಯ ಹೆಸರಿನಿಂದ ಬದಲಿ ಮಾಡಿ.

`<functions_app_name>` ಅನ್ನು ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್‌ಗಾಗಿ ಅನನ್ಯ ಹೆಸರಿನಿಂದ ಬದಲಿ ಮಾಡಿ. ಇದು ಜಾಗತಿಕವಾಗಿ ವಿಶಿಷ್ಟವಾಗಿರಬೇಕು ಏಕೆಂದರೆ ಇದು ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್‌ಗೆ ಪ್ರವೇಶಿಸಲು ಬಳಸಬಹುದಾದ URL ಭಾಗವಾಗುತ್ತದೆ. `soil-moisture-sensor-` ಅಥವಾ ಅದಕ್ಕೆ ಸಂಬಂಧಿಸಿದ ಅನನ್ಯ ಐಡಿಯಂಟಿಫೈಯರ್, ಕೆಲವು ಯಾದೃಚ್ಛಿಕ ಪದಗಳು ಅಥವಾ ನಿಮ್ಮ ಹೆಸರು ಸೇರಿಸಿ ಬಳಸಬಹುದು.

`--functions-version 3` ಆಯ್ಕೆ Azure Functions ನ ಆವೃತ್ತಿಯನ್ನು 3 ಆಗಿ ಹೊಂದಿಸುತ್ತದೆ. ಆವೃತ್ತಿ 3 ಹೊಸದು.

`--os-type Linux` ಆಯ್ಕೆ ಫಂಕ್ಷನ್ಸ್ ರನ್‌ಟೈಮ್‌ಗೆ ಈ ಕಾರ್ಯನಿರ್ವಹಣೆಗಾಗಿ ಲಿನಕ್ಸ್ನೊಂದಿಗೆ OS ಅನ್ನು ಬಳಸಲು ತಿಳಿಸುತ್ತದೆ. ಫಂಕ್ಷನ್ಸ್ ಅನ್ನು ಲಿನಕ್ಸ್ನಲ್ಲಿಯೂ ಅಥವಾ ವಿಂಡೋಸ್‌ನಲ್ಲಿಯೂ ಹೋಸ್ಟ್ ಮಾಡಬಹುದು, ಭಾಷೆ ಅವಲಂಬಿಸಿ. Python ಆ್ಯಪ್ ಗಳು ಕೇವಲ ಲಿನಕ್ಸ್‌ನಲ್ಲಿ ಮಾತ್ರ ಬೆಂಬಲಿತವಾಗಿವೆ.

### ಕಾರ್ಯ - ನಿಮ್ಮ ಆ್ಯಪ್ ಸೆಟ್ಟಿಂಗ್ಸ್ ಅಪ್ಲೋಡ್ ಮಾಡು

ನೀವು ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಅನ್ನು ಅಭಿವೃದ್ಧಿಪಡಿಸುವಾಗ, `local.settings.json` ಫೈಲ್ ನಲ್ಲಿ ನಿಮ್ಮ IoT ಹಬ್ ಸಂಪರ್ಕ ಸ್ಟ್ರಿಂಗ್‌ಗಳಿಗೆ ಕೆಲವು ಸೆಟ್ಟಿಂಗ್ಸ್ ಅನ್ನು შენಿಸಿಕೊಂಡಿದ್ದೀರಿ. ಈವೆ ನಿಮ್ಮ ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಗೆ Azure ನಲ್ಲಿ ಆಪ್ಲಿಕೇಶನ್ ಸೆಟ್ಟಿಂಗ್ಸ್ ಆಗಿ ಬರೆಯಬೇಕು, ಇದರಿಂದ ನಿಮ್ಮ ಕೋಡ್‌ನಲ್ಲಿ ಬಳಕೆ ಮಾಡಬಹುದು.

> 🎓 `local.settings.json` ಫೈಲ್ ಸ್ಥಳೀಯ ಅಭಿವೃದ್ಧಿಗಾಗಿ ಮಾತ್ರ; ಮತ್ತು ಈ ಫೈಲ್ ಅನ್ನು GitHub ಮುಂತಾದ ಮೂಲ ನಿಯಂತ್ರಣದಲ್ಲಿ ಸೇರಿಸಬಾರದು. ಕ್ಲೌಡ್‌ಗೆ ನಿಯೋಜಿಸಿರುವಾಗ, ಆಪ್ಲಿಕೇಶನ್ ಸೆಟ್ಟಿಂಗ್ಸ್ ಗಳನ್ನು ಇಡಲಾಗುತ್ತದೆ. ಆಪ್ಲಿಕೇಶನ್ ಸೆಟ್ಟಿಂಗ್ಸ್ ಕೀ/ಮೌಲ್ಯ ಜೋಡಿಗಳಾಗಿದ್ದು, ಕ್ಲೌಡ್ ನಲ್ಲಿ ಹುಟ್ಟುಹೊಡೆಯಲ್ಪಡುವದು ಮತ್ತು ಎನ್ವಿರಾನ್ಮೆಂಟ್ ಮೌಲ್ಯಗಳಿಂದ ನೀವು ಅಥವಾ ರನ್‌ಟೈಮ್ ನಿಮ್ಮ ಕೋಡ್‌ಗೆ ಅಥವಾ IoT ಹಬ್‌ಗೆ ಸಂಪರ್ಕ ಮಾಡಲು ಓದಲಾಗುತ್ತದೆ.

1. ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಆಪ್ಲಿಕೇಶನ್ ಸೆಟ್ಟಿಂಗ್ಸ್ ನಲ್ಲಿ `IOT_HUB_CONNECTION_STRING` ಸೆಟ್ಟಿಂಗ್ ನ್ನು ಹೊಂದಿಸಲು ಕೆಳಗಿನ ಆಜ್ಞೆಯನ್ನು ಚಾಲನೆ ಮಾಡಿ:

    ```sh
    az functionapp config appsettings set --resource-group soil-moisture-sensor \
                                          --name <functions_app_name> \
                                          --settings "IOT_HUB_CONNECTION_STRING=<connection string>"
    ```

`<functions_app_name>` ಅನ್ನು ನೀವು ಬಳಸಿದ ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಹೆಸರಿನಿಂದ ಬದಲಿ ಮಾಡಿ.

`<connection string>` ಅನ್ನು ನಿಮ್ಮ `local.settings.json` ಫೈಲಿನ `IOT_HUB_CONNECTION_STRING` ಮೌಲ್ಯದೊಂದಿಗೆ ಬದಲಿ ಮಾಡಿ.

1. ಮೇಲಿನ ಹಂತವನ್ನು ಪುನರಾವರ್ತಿ ಮಾಡಿ, ಆದರೆ `REGISTRY_MANAGER_CONNECTION_STRING` ಗೆ `local.settings.json` ಫೈಲಿನ ಹೊಂದಬೇಕರಾಗುವ ಮೌಲ್ಯವನ್ನು ಬಡಲಿ ಮಾಡಿ.

ನೀವು ಈ ಆಜ್ಞೆಗಳನ್ನು ಚಲಾಯಿಸಿದಾಗ, ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಗೆ ಎಲ್ಲಾ ಆಪ್ಲಿಕೇಶನ್ ಸೆಟ್ಟಿಂಗ್ಸ್ ಗಳ ಪಟ್ಟಿ ಕೂಡಾ ಹೊರಬರುತ್ತದೆ. ನಿಮ್ಮ ಮೌಲ್ಯಗಳು ಸರಿಯಾಗಿ ಹೊಂದಿರುವುದನ್ನು ಪರಿಶೀಲಿಸಲು ಇದನ್ನು ಉಪಯೋಗಿಸಬಹುದು.

> 💁 ನೀವು `AzureWebJobsStorage` ಗೆ ಈಗಾಗಲೇ ಹೊಂದಿಸಿದ ಮೌಲ್ಯವನ್ನು ಕಾಣಬಹುದು. ನಿಮ್ಮ `local.settings.json` ಫೈಲ್‌ ನಲ್ಲಿ ಇದು ಸ್ಥಳೀಯ ಸಂಗ್ರಹ ಅನೂಕರಣಾರ್ಥದೆ ಬಳಸಲು ಹೊಂದಿದ್ದ ಮೌಲ್ಯ. ನೀವು ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಸೃಷ್ಟಿಸಿದಾಗ ಸಂಗ್ರಹ ಖಾತೆಯನ್ನು ಪ್ಯಾರಾಮೀಟರ್ ಆಗಿ ನೀಡಿದೀರಿ, ಇದು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಈ ಸೆಟ್ಟಿಂಗ್ ನಲ್ಲಿ ಹೊಂದಿಗೊಳ್ಳುತ್ತದೆ.

### ಕಾರ್ಯ - ನಿಮ್ಮ ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಅನ್ನು ಕ್ಲೌಡ್ ಗೆ ನಿಯೋಜಿಸು

ಈಗ ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಸಿದ್ಧವಾಗಿದೆ, ನಿಮ್ಮ ಕೋಡ್ ಅನ್ನು ನಿಯೋಜಿಸಬಹುದು.

1. VS ಕೋಡ್ ಟರ್ಮಿನಲ್ ನಿಂದ ಕೆಳಗಿನ ಆಜ್ಞೆಯನ್ನು ಚಾಲನೆ ಮಾಡಿ ನಿಮ್ಮ ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಅನ್ನು ಪ್ರಕಟಿಸು:

    ```sh
    func azure functionapp publish <functions_app_name>
    ```

`<functions_app_name>` ಅನ್ನು ನೀವು ಬಳಸಿದ ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಹೆಸರಿನಿಂದ ಬದಲಿ ಮಾಡಿ.

ಕೋಡ್ ಪ್ಯಾಕೇಜ್ ಆಗಿ ಫಂಕ್ಷನ್ಸ್ ಆ್ಯಪ್ ಗೆ ಕಳುಹಿಸಲಾಗುತ್ತದೆ, ಅಲ್ಲಿ ಇದು ನಿಯೋಜಿಸಲ್ಪಟ್ಟು ಪ್ರಾರಂಭವಾಗುತ್ತದೆ. ಬಹಳಷ್ಟು ಕಾನ್ಸೋಲ್ ಔಟ್ ಪಟುಟ್ ಬರುತ್ತದೆ, ನಿಯೋಜನೆಯ ದೃಢೀಕರಣ ಮತ್ತು ನಿಯೋಜಿಸಲಾದ ಫಂಕ್ಷನ್ಸ್ ಪಟ್ಟಿ ಮೂಲಕ ಅಂತ್ಯಗೊಳ್ಳುತ್ತದೆ. ಈ ಪ್ರಕರಣದಲ್ಲಿ ಪಟ್ಟಿ ಟ್ರಿಗ್ಗರ್ ಮಾತ್ರ ಸೇರಿರುತ್ತದೆ.

```output
Deployment successful.
Remote build succeeded!
Syncing triggers...
Functions in soil-moisture-sensor:
    iot-hub-trigger - [eventHubTrigger]
```

ನಿಮ್ಮ IoT ಸಾಧನದಲ್ಲಿ ಚಾಲನೆ ಇರಲಿ. ಮಣ್ಣಿನ ತಂಪಾಗು ಮಟ್ಟವನ್ನು ಬದಲಾಯಿಸಿ ಅಥವಾ ಸಂವೇದಕವನ್ನು ಮಣ್ಣಿನ ಒಳಗೆ ಮತ್ತು ಹೊರಗೆ ಸರಿಸಿ. ಮಣ್ಣು ತಂಪಾಗುವಿಕೆ ಬದಲಾಗುವಂತೆ ರಿಲೇ ಆನ್ ಮತ್ತು ಆಫ್ ಆಗುವುದು ಕಾಣಬಹುದು.
